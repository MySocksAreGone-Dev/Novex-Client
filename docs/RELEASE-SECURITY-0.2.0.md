# v0.2.0 release security review

- Scanned current source, ignored local environment configuration, generated frontend, and all 374 reachable Git objects. No privileged credentials found. Public Supabase anon configuration and Microsoft's public application ID are intentional. Token-like test values are synthetic.
- Reviewed main/preload boundaries, registered instance paths, symlink/traversal checks, OS-backed session storage, argument-array process spawning, and token-redacted diagnostics. Renderer isolation and sandboxing remain enabled; window creation and permissions are denied.
- Inspected the live Novex Supabase policy/function catalog: all application tables have RLS; ordinary users cannot write admin roles or invoke verified-account linking. Messages require an accepted friendship and the authenticated sender. Home writes require the private admin registry. Synced the older fresh-install SQL with those existing social restrictions and added a database regression test. No production database data or schema was modified.
- Updated Electron to 43.5.0 for the reported sandbox/preload security fixes; updated affected compatible Axios, Undici and brace-expansion transitive packages. Production npm dependency audit is clear.
- Remaining build-only advisory: `http-cache-semantics` GHSA-ch52-4w7c-c8xp, transitively used by electron-builder's downloader. At review time its latest version is 4.2.0 and remains affected. This build fetches public Electron assets without user credentials and does not use a multi-user authenticated HTTP cache; the affected packages are not shipped in the application. No major build-tool rewrite or unsupported override was applied.
- Supabase's leaked-password protection is disabled. Enable it in Auth settings when supported by the project plan. Private deny-by-default tables and deliberately scoped SECURITY DEFINER RPCs also produce expected advisor notices; their grants and authorization checks were reviewed.
- This review is not a penetration test. Windows gameplay, real Microsoft sign-in and installer behavior still require platform testing. Installers are unsigned; no signing secrets or fake certificates are included.

## Validation

TypeScript, 42 automated tests, production frontend build and Electron syntax checks passed. The packaged Linux application started with isolated test data and its preload IPC worked with Node access disabled in the renderer. Both application archives were checked against current source; the Linux archive's 1,939 files were additionally scanned for credential literals. Linux AppImage, RPM and DEB packages were generated freshly; version and architecture metadata were checked. Local Windows cross-builds failed in Wine, including an isolated-prefix retry; incomplete installers are excluded. The existing native Windows GitHub Actions job is used for the release installer. CI assets must be verified before publishing the draft release.
